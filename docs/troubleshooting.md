# 问题排查

从实际失败的阶段开始，完成一项后再继续下一项。先记录原始现象，避免一次修改多个设置；每次只改变一个因素，保留前后结果。

| 现象 | 检查入口 | 本阶段完成标志 |
| --- | --- | --- |
| 版本不存在、下载失败 | [版本与下载](#version) | 获取到指定版本的依赖 |
| 编译失败、找不到模块 | [安装与编译](#install) | 依赖安装、编译均成功 |
| 厂商模块缺失、框架加载失败 | [依赖与框架](#dependencies) | 所需产品正确链接与嵌入 |
| Bundle 缺失、资源异常 | [资源](#resources) | 最终 App 资源核对通过 |
| SDK 初始化失败 | [初始化](#initialize) | 收到明确的初始化成功结果 |
| 无广告、加载或展示失败 | [加载与展示](#ads) | 对应样式可见展示并有预期回调 |
| 返回页面或回调异常 | [生命周期](#lifecycle) | 对象和页面状态符合预期 |

<a id="version"></a>
## 版本与下载

1. 记录安装方式和精确版本：Pod 索引、Git Tag、SPM 或手动文件，不能仅写“最新版”。
2. 按实际渠道检查：Pods 索引可运行 `pod spec which JAdbid --version=1.0.0`；Git Tag 可运行 `git ls-remote --tags https://github.com/jiguangads/jadbid-ios-sdk.git refs/tags/1.0.0`。SPM 使用同一 Git Tag。两项结果分别判断，不能相互替代。
3. 区分“索引未找到”与“网络下载失败”。本地 Pod 索引过期时可刷新对应索引后重试；Tag 或渠道版本不可用时，提供查询结果请求确认，不切换到不明来源。

**仍失败：** 提交安装命令、对应渠道、脱敏错误片段和发生时间；私有源 URL 先脱敏。

<a id="install"></a>
## 安装与编译

1. 检查 iOS 至少 15.0，目标是 arm64 真机或 arm64 模拟器；不支持 x86_64 模拟器。
2. 先处理依赖安装命令的首个错误。Pods 示例打开 `.xcworkspace`，并确认正在构建的 scheme、target 和设备正确。
3. 核对实际安装版本与所选源；Pods 查看 `Podfile.lock`，SPM 查看 `Package.resolved` 及 Xcode 中的精确版本。只摘取相关条目，分享前删去私有源信息。
4. 若为链接错误，继续下一节，不通过删除全部缓存或任意升级厂商 SDK 掩盖原因。

**完成标志：** 依赖安装无错误，目标 App 能编译。

<a id="dependencies"></a>
## 依赖与框架

1. 确认安装了 Core、所选 Adapter 和对应厂商 SDK；不要在同一 target 由多个安装方式重复引入 JAdbid。
2. SPM 需单独添加厂商官方产品和真实传递依赖，版本与资源要求以[集成指南](integration.md)为准。纯 OC 宿主还需核对指南中的 Swift 库搜索路径。
3. JAdbid 静态框架选择 **Do Not Embed**；厂商动态框架按官方要求嵌入并签名。框架路径、切片与构建目标一致。

**仍失败：** 提供首条编译或框架加载错误、相关依赖版本及脱敏的链接/嵌入设置截图。

<a id="resources"></a>
## 资源

1. 核对实际安装方式及所选源，按[原生 SPM 资源表](integration.md#原生-spm-资源布局)或 Pods 实际资源布局检查，不能只按 Bundle 名称推断内容。
2. Pods 先确认安装及资源阶段无错误；SPM、手动集成按指南在签名前处理资源。Bigo 还需核对实际嵌入框架内资源和隐私清单。
3. 需要脚本核对时使用真实 SDK、厂商资源、App 目录和对应的 `--integration`、`--source`，构建后追加 `--verify-final` 只读检查。

**完成标志：** 最终 App 中的所需资源和隐私清单与来源一致。不要修改已签名 App 补资源，也不要从其它版本拷入同名 Bundle。

<a id="initialize"></a>
## 初始化

1. 确认应用配置非空且与当前应用匹配；示例中的 `SampleConfig.plist` 默认为空。系统授权、示例页面确认和 SDK 初始化分别判断。
2. 宿主完成适用的隐私流程后显式初始化，等待明确成功或失败；初始化失败时先停止广告操作。
3. 按[日志说明](integration.md#调试日志与运行检查)获取复现时段的脱敏记录，保留失败阶段、错误码及有限原因，不附真实 App ID。

**仍失败：** 提供初始化步骤、结果、设备和网络环境；不要仅描述“没有广告”。

<a id="ads"></a>
## 加载与展示

1. 先确认初始化成功，再核对广告位所属应用、广告样式、所选源及平台配置。
2. 区分网络不可用、请求超时、暂无填充等实际结果；保留脱敏错误码和有限原因，不自行猜测错误含义或承诺重试必定成功。
3. 加载中等待明确结果，避免重复点击、并发请求或无限重试。加载成功后再按对应样式的示例检查展示入口、页面状态、尺寸或窗口等条件。
4. 在真机验证可见展示及回调；激励视频额外核对奖励回调。回调与对应那次请求关联，不能拿上一次成功代替本次结果。

**仍失败：** 提供最后成功阶段、复现步骤、广告样式、脱敏时段日志及截图。真实广告配置通过约定的安全渠道核对，不放公开工单。

<a id="lifecycle"></a>
## 页面返回与回调

保留仍有效页面持有的广告对象，真正退出页面时再释放。加载失败结束本次请求；不要依赖后台缓存可用性变化自动产生新的加载回调。对照[示例生命周期说明](../demo/README.md#生命周期与日志)检查对象是否提前释放、回调是否属于当前页面。

**仍失败：** 提供最短操作顺序、前后台或页面切换时机，以及对应回调时间线。

无法定位时，使用[技术支持手册](technical-support.md#template)提交已检查项和脱敏复现材料。
