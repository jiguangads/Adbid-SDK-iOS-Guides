# FAQ

这里先给简要答复。需要逐步检查时看[问题排查](troubleshooting.md)，第一次接入看[快速集成](quick-start.md)。

<a id="platform"></a>
## 支持哪些系统和设备？为什么 Intel Mac 模拟器不能编译？

最低 iOS 15.0，真机和模拟器均提供 arm64 切片，不支持 x86_64 模拟器。请先核对机器、构建目标和架构；不要通过修改设置强行生成包内不存在的切片。详见[安装与编译排查](troubleshooting.md#install)。

<a id="version"></a>
## 找不到 1.0.0，或者安装时提示版本不存在，怎么办？

先区分安装渠道：普通 Pod 版本声明依赖 CocoaPods 索引；SPM 精确版本和示例 Podfile 的 Git 引用依赖 SDK 仓库中对应 Tag。仓库有文件不代表所有渠道都能安装。核对实际渠道、版本及错误，再按[版本检查步骤](troubleshooting.md#version)处理；不要把其它版本改名当成 1.0.0。

## 首次接入应该选择哪种方式？

先按[快速集成](quick-start.md)运行 Pods 示例，确认一个广告源和一种样式。项目采用 SPM 时按[完整集成指南](integration.md#swift-package-manager)配置；两种方式的厂商依赖和资源处理不同。

## 只安装 Core 就能使用所有广告源吗？

Core 是基础模块。使用某个广告源还需对应 Adapter 及厂商 SDK；选择方式见[集成指南](integration.md)。首次接入先验证单源，避免同时引入多项变量。

## SPM 已添加 JAdbid，为什么仍提示找不到厂商模块？

JAdbid 的 Swift 包不自动安装厂商 SDK。须添加所选源的官方产品及传递依赖，再核对 target 链接和资源；仅选中 JAdbid Adapter 产品不等于安装完成。先按[厂商产品与固定版本](integration.md#厂商产品与固定版本)选择，再按[依赖与框架排查](troubleshooting.md#dependencies)检查。

## 已执行 pod install，为什么 Xcode 还是找不到模块？

先确认打开的是 `Sample.xcworkspace`，依赖安装无错误，所需模块属于当前 target，再看架构和版本是否匹配。不要先删除所有缓存或升级全部依赖。详见[安装与编译排查](troubleshooting.md#install)。

## 为什么提示缺少 Bundle，或者启动时报资源错误？

先确认 Pods、原生 SPM 或手动集成方式，再按所选源检查真实 App 内的资源。Pods 正常安装处理其资源；SPM 和手动集成须按指南在签名前复制。不要混用不同渠道的同名 Bundle。详见[资源排查](troubleshooting.md#resources)。

## 所有框架都应该选 Embed & Sign 吗？

JAdbid 自身是静态框架，应选择 **Do Not Embed**（只链接、不嵌入）；厂商动态框架按官方要求 **Embed & Sign**（嵌入并签名）。请区分具体框架，不能对所有依赖统一修改。详见[完整集成指南](integration.md)。

<a id="config"></a>
## App ID、广告位 ID 和厂商 App ID 有什么区别？

JAdbid App ID 用于 SDK 应用初始化；广告位用于对应样式的广告请求；厂商可能另有自己的应用配置。三者不能互相替换。示例字段见[快速集成](quick-start.md#3-填写本地示例配置)，真实值只在本地或适用的安全渠道核对，不贴入公开日志。

## Demo 显示“尚未初始化”，是不是安装失败？

不是。Demo 默认不自动初始化或请求广告。先填本地配置、完成隐私流程，再显式初始化；只有初始化成功后才进入广告操作。步骤见[快速集成](quick-start.md#4-构建并初始化)。

<a id="privacy"></a>
## 点击 Demo 的隐私确认，就等于已取得 ATT 授权吗？

不等于。示例页面确认和系统授权是不同状态，宿主仍负责适用的隐私流程、系统权限描述及隐私申报。不要为了排查而跳过授权流程或强制设置同意状态。详见[完整集成指南](integration.md#初始化隐私与生命周期)。

## 初始化失败、广告加载失败，应该先排查哪一个？

先解决初始化失败，再排查单个广告位的加载与展示。初始化成功只证明该阶段成功，不保证广告有填充。按[问题排查](troubleshooting.md)确认最后成功的阶段，记录错误码和已脱敏的有限原因。

## 加载失败或没有广告，是否一定是 SDK 的问题？

不能仅凭这个现象判断。需要核对初始化、广告位样式、网络、平台配置、依赖和实际错误；暂无填充也不能靠反复点击加载来保证解决。按[加载与展示排查](troubleshooting.md#ads)收集证据后判断。

## 加载中、加载成功和展示成功是同一件事吗？

不是。加载中需等待明确结果；加载成功后还需满足对应样式的展示条件，可见展示与回调也要分别确认。不要用页面出现或模拟器启动代替实际广告验证。详见[加载与展示排查](troubleshooting.md#ads)。

## 可以反复调用资源脚本，把多个源依次复制到同一个 App 吗？

不可以。当前脚本每次只处理一个源，会拒绝其它源资源污染，不能靠顺序调用叠加多源。完整约束见[资源说明](integration.md#资源复制)；需要进一步确认组合时按[技术支持手册](technical-support.md)提供接入方式和源列表。

## 为什么 Release 没有普通事件日志？需要上传哪些日志？

Release 默认关闭普通事件，保留精简错误；可在初始化前按指南开启调试，复现后恢复应用原配置。筛选 `[JAdbid]`、`[JAdbidDemo]`，只提供复现时段的脱敏片段。不要上传完整原始日志、请求体或设备标识，材料范围见[技术支持手册](technical-support.md#materials)。

## 需要帮助时，怎样描述问题才完整？

写清“最后成功的阶段、预期与实际、版本及环境、复现步骤、实际错误、已检查项”，附脱敏日志和截图。可直接填写[支持请求模板](technical-support.md#template)。
