# 技术支持手册

本手册用于确认集成问题、组织排查步骤和提交支持请求。第一次接入看[快速集成](quick-start.md)，技术参数看[完整集成指南](integration.md)，简要答复看 [FAQ](faq.md)。

## 提交入口

公开问题可通过本仓库的 [GitHub Issues](https://github.com/jiguangads/Adbid-SDK-iOS-Guides/issues/new) 提交，登录后使用下方[支持请求模板](#template)。提交前检查正文和所有附件已脱敏。

涉及真实广告配置、账号或其它敏感信息时，先通过已有支持联系渠道确认安全接收方式；不要将这些材料附在公开 Issue 中。

## 先确认问题在哪一步

询问“最后成功完成哪一步、接下来做了什么、预期和实际分别是什么”，按下表继续：

| 当前情况 | 建议确认 | 下一步 |
| --- | --- | --- |
| 无法安装或编译 | 版本、安装方式、设备架构和首条错误 | [安装与编译排查](troubleshooting.md#install) |
| 能启动，尚未初始化 | 配置是否填写、是否执行初始化、隐私流程状态 | [快速集成第 4 步](quick-start.md#4-构建并初始化) |
| 初始化明确失败 | 初始化错误、配置是否匹配、复现环境 | [初始化排查](troubleshooting.md#initialize) |
| 初始化成功，无广告 | 广告样式、加载结果、平台配置与网络 | [加载与展示排查](troubleshooting.md#ads) |
| 已加载，未展示或回调异常 | 展示入口、页面状态、对象持有和回调时间线 | [展示排查](troubleshooting.md#ads)、[生命周期排查](troubleshooting.md#lifecycle) |

不根据“没有广告”直接判定 SDK 故障，也不以构建成功、页面出现或暂无填充作为完整广告验证结论。

## 一次确认的基本信息

- SDK 精确版本、厂商 SDK 版本，以及使用 OC 还是 Swift。
- 安装方式：CocoaPods、原生 SPM 或手动集成；所选广告源与广告样式。
- Xcode、系统版本、设备型号，真机还是模拟器。
- 问题发生时间与时区、复现频率；最后成功阶段。
- 预期结果、实际结果、首条实际错误和已做的检查。

确认配置时先问“是否填写、是否匹配”，不要要求将真实 App ID、广告位或设备标识贴到公开交流中。

## 提供哪些材料

| 材料 | 应包含 | 分享前处理 |
| --- | --- | --- |
| 复现步骤 | 从启动到失败的最短操作，是否切换页面或前后台 | 去掉真实账号及业务内容 |
| 日志片段 | 同一次复现时段的阶段、时间、错误码及有限原因；可筛选 `[JAdbid]`、`[JAdbidDemo]` | 移除 App ID、广告位、IDFA、设备标识、令牌、请求体及原始厂商对象 |
| 截图或短录屏 | 失败提示、页面状态、必要的 target/框架设置 | 遮盖配置、标识和业务信息 |
| 依赖片段 | 相关的 `Podfile.lock` 条目，或 SPM 精确版本与相关 `Package.resolved` 条目 | 移除私有源地址、访问参数与凭据 |
| 最小复现工程 | 能复现问题的最小代码与必要设置 | 移除真实配置、签名证书、描述文件、账号及 Token |

先自行打开将要发送的文件，确认已脱敏且仍能看出问题。不要上传完整原始日志、整个业务工程或签名材料。确需核对真实配置时，使用双方约定的安全渠道，不在公开工单中补充。

## 哪些情况需要进一步技术排查

- 按对应排查步骤核对后，在支持的环境中仍可稳定复现。
- 发生崩溃、卡死，或加载/展示/回调结果与实际操作明显不一致。
- 需要解释尚未确认的错误、依赖冲突、多源资源组合或特定厂商行为。

崩溃应提供脱敏的系统崩溃报告、发生时间、设备环境和最小步骤；不要只提供最后一行日志。尚不能定位时明确“待进一步确认”，列出缺失材料与下一步，不承诺未经验证的原因、修复时间或绕过方式。

## 支持请求模板

复制以下内容并填写；没有结果的项写“未检查”，不要填成通过。

```text
问题摘要：
SDK 精确版本 / 厂商版本：
安装方式 / 语言：
广告源 / 广告样式：
Xcode / 系统 / 设备 / 真机或模拟器：
发生时间与时区 / 复现频率：
最后成功阶段：
最短复现步骤：
预期结果：
实际结果 / 错误码 / 有限原因：
已检查项及对应结果：
已脱敏附件：
仍需确认的信息：
```

## 回复时说明什么

先复述已确认的现象，再给一至三项可执行检查，并说明每项的成功标志。避免一次罗列所有技术参数。

例如：“目前已确认可以启动，但尚未初始化。请先检查本地 `SampleConfig.plist` 的必填配置，再完成应用所需隐私流程并显式初始化。预期页面显示初始化成功；如失败，请按上述模板提供该时段的脱敏错误记录。”

提交后保留材料版本和检查结果。补充新结果时说明改变了哪项配置，复测同一路径；结论只覆盖实际复现的环境与步骤。
